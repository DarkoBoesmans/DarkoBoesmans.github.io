## The Human Context

Designing for healthcare isn't like designing for e-commerce or finance. The stakes are fundamentally different:

- Users are often stressed, anxious, or in pain
- Digital literacy varies dramatically (ages 18-95)
- Mistakes can have serious health consequences
- Privacy isn't a feature—it's a legal and ethical requirement

### Research Process

We spent weeks in hospital waiting rooms, observing and interviewing patients:

> "I just want to know when my appointment is without calling and waiting on hold for 20 minutes."
> — Maria, 67, arthritis patient

This quote became our North Star: **reduce friction, increase clarity**.

## Security & Accessibility Balance

### Passwordless Authentication

Traditional passwords create barriers for elderly users. We implemented WebAuthn:

```typescript
// Biometric authentication flow
async function authenticatePatient(patientId: string) {
  const challenge = await server.getChallenge(patientId);
  
  const credential = await navigator.credentials.get({
    publicKey: {
      challenge: challenge,
      rpId: 'hospital.be',
      userVerification: 'required',
    },
  });
  
  return server.verify(credential);
}
```

Benefits:
- No passwords to remember
- Phishing-resistant
- Works with fingerprint, face recognition, or device PIN
- Falls back to SMS for users without biometric devices

### GDPR by Design

Every feature was built with privacy as a default:

1. **Data Minimization**: Only collect what's strictly necessary
2. **Explicit Consent**: Clear, granular consent dialogs
3. **Right to Erasure**: One-click data export and deletion
4. **Audit Logging**: Complete trail of data access

## Accessibility Implementation

Achieving WCAG 2.2 AAA required attention to every detail:

### Typography for Low Vision

```css
/* Minimum 18px base size, scalable to 200% */
:root {
  --text-base: clamp(1.125rem, 2vw, 1.25rem);
}

@media (prefers-contrast: more) {
  :root {
    --text-base: 1.25rem;
    --color-text: #000000;
    --color-background: #ffffff;
  }
}
```

### Cognitive Load Reduction

- Progressive disclosure: Show only essential information first
- Consistent navigation patterns across all pages
- Plain language (B1 reading level) instead of medical jargon
- Confirmation dialogs for critical actions

### Motor Impairment Support

- All touch targets minimum 60×60px (exceeds 44px requirement)
- Keyboard navigation for all interactive elements
- Voice control compatibility testing
- Extended timeout periods for form completion

## Reflections

This project taught me that **inclusive design isn't charity—it's good design**. Features we built for elderly users (clear typography, simple navigation, explicit feedback) improved the experience for everyone.

The biggest challenge wasn't technical—it was earning trust. Patients needed to feel confident that their sensitive health data was secure. By being transparent about data usage and giving users complete control, we achieved 78% adoption without a single marketing campaign.

Healthcare technology has the power to reduce inequality in health outcomes. That responsibility shapes how I approach every design decision.
